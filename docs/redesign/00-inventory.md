| :--- | :--- | :--- |
| **إطار العمل (Framework)** | **Flutter Web 3.47.7** (Dart 3.13.5, Channel Stable) | بناء واجهات التطبيق متعددة المنصات (Desktop / Tablet / Mobile). |

## 🚀 2. أوامر التشغيل والتحقق (Commands Used to Run & Verify)

1. **التحقق من حزم Flutter والاعتماديات**:
   ```bash
   flutter doctor -v
   flutter pub get
   flutter test
   ```
2. **بناء واختبار تطبيق الويب للإنتاج**:
   ```bash
   flutter build web --profile
   # أو للأداء الأمثل بدون wasm dry-run:
   flutter build web --release --pwa-strategy=offline-first
   ```
3. **تشغيل خادم الويب المحلي للمعاينة وسيناريوهات الفحص السريري**:
   ```bash
   # تشغيل خادم محلي ثابت يخدم مخرجات الويب المجمعة:
   python3 -m http.server 8081 --directory build/web
   # الرابط الرئيسي المباشر: http://127.0.0.1:8081
   # رابط المعاينة السريرية المباشرة (Demo Gate): http://127.0.0.1:8081/#/demo
   ```
4. **تشغيل أداة الفحص البصري التلقائي (Playwright Visual Capture)**:
   ```bash
   npm install -D playwright
   node scripts/capture_all_screens.js
   ```

## 🗂️ 3. حصر شامل لكافة الشاشات، الصفحات، والمسارات (Screens & Routes Inventory)

### أ. بوابات الدخول والمصادقة (Auth & Onboarding Shell)
1. **شاشة تسجيل الدخول (`/login` - `LoginScreen`)**:
   - حقول البريد الإلكتروني، كلمة المرور، تذكر الحساب، زر الدخول، زر استعادة كلمة المرور، وبوابة الانتقال إلى التسجيل.
2. **شاشة التسجيل المتقدمة (`/register` - `RegisterScreen`)**:
   - نموذج متعدد الخطوات (`AppStepper` 1 إلى 4): بيانات الطبيب، بيانات العيادة والتخصص، رمز الدعوة، وتأكيد الحساب.
3. **شاشة استعادة وتعيين كلمة المرور (`/reset` - `ResetPasswordScreen`)**:
   - وضعين: وضع طلب رابط الاستعادة بالبريد، ووضع إدخال كلمة المرور الجديدة وتأكيدها.
4. **شاشات الحالات الخاصة بالاشتراك والحساب**:
   - **`AccountBlockedScreen`**: شاشة الحساب المحظور أو المجمد.
   - **`PendingActivationScreen`**: شاشة انتظار تفعيل العيادة من الإدارة.
   - **`JoinClinicScreen`**: شاشة الانضمام لعيادة قائمة برمز دعوة.
   - **`SubscriptionGateScreen`**: بوابة حجب الوصول عند انتهاء الاشتراك.
   - **`TopUpSubscriptionScreen`**: شاشة شحن الباقة وتجديد الاشتراك.
   - **`VerifyOtpScreen`**: إدخال رمز التحقق (OTP) للرسائل.

### ب. منصة الإدارة السريرية الرئيسية (`DashboardScreen` & `AppShell`)
1. **تبويب الرئيسية / نظرة عامة (`_HomeTab` / `/home`)**:
   - ترويسة الترحيب بالطبيب والمريض النشط (`DashboardGreetingHero`).
   - صف المؤشرات الحيوية (`DashboardStatsRow`): إيراد اليوم، مواعيد اليوم، الكشوفات المكتملة، مرضى الانتظار.
   - شريط الإجراءات السريعة (`DashboardQuickActions`): مريض جديد، حجز موعد، بدء الكشف، تقارير اليوم.
   - رسم بياني للإيرادات الأسبوعية (`DashboardWeeklyChart`).
   - قائمة مواعيد اليوم وقائمة الانتظار السريعة (`DashboardTodayList`).
   - سجل المعاملات المالية الحديثة وطرق الدفع (`DashboardRecentTransactions`).
2. **تبويب لوحة المواعيد والطابور السريري (`AppointmentsScreen` / `/appointments`)**:
   - شريط فلترة التواريخ والحالات: الكل، بالانتظار، مع الطبيب، مكتمل، ملغي.
   - مفتاح التبديل بين العرض المدمج (`قائمة مدمجة`) وطابور المراحل (`طابور المراحل`).
   - بطاقات الحجز في الطابور (`AppointmentCard`, `QueueCard`, `QueueTimelineRow`).
   - درج التفاصيل السريرية الجانبي للموعد (`AppointmentDetailsCard`): بيانات الزيارة، الحساب المالي، الخدمات المضافة، الإجراءات السريرية.
3. **تبويب سجل ودليل المرضى (`PatientsPage` / `/patients`)**:
   - حقل البحث والفلترة (`AppSearchBar`, شريحة البحث برقم الملف).
   - قائمة المرضى المدمجة مع أرقام الملفات وحالات المتابعة.
   - اللوحة التفصيلية لملف المريض الإلكتروني (`PatientMedicalProfileView`):
     - بيانات المريض، العمر، رقم الهاتف، العنوان.
     - تنبيه الحساسيات الدوائية والأمراض المزمنة.
     - خط زمني تفصيلي لكافة الزيارات والتشخيصات السابقة.
     - أزرار فحص المريض وحجز موعد جديد.
4. **قمرة قيادة الفحص السريري (`ExaminationScreen`)**:
   - شريط العلامات الحيوية (`ClinicalVitalsRibbon`): الضغط، النبض، الحرارة، الوزن، الطول، السكر.
   - نموذج التوثيق السريري (`ExaminationForm`):
     - الشكوى الرئيسية (Chief Complaint).
     - التشخيص الطبي السريري (Diagnosis) مع شرائح التشخيصات الشائعة.
     - الروشتة والخطة العلاجية (Rx & Treatment Plan) مع شرائح الأدوية السريعة.
     - الخدمات الطبية والإجراءات المضافة وأسعارها.
   - شريط جانبي لحالة الطابور اليومي المباشر وملاحظات المريض السابقة.
   - أزرار إنهاء الكشف واعتماد التقرير، وحفظ المسودة.
5. **تبويب التقارير والمؤشرات المالية (`ReportsScreen` / `/reports`)**:
   - محدد النطاق الزمني: نظرة عامة، السجلات اليومية، السجلات الشهرية، تقفيل الخزينة.
   - بطاقات الإيرادات: اليوم، الأسبوع، الشهر.
   - رسم بياني بيئي لتوزيع حالات الكشوفات (Donut Chart).
   - رسم بياني خطي لمسار الإيرادات اليومية وتذبذب الدخل.
   - شاشة التفاصيل والتقسيم المالي (`ReportDetailScreen`).
6. **تبويب الإعدادات والتهيئة (`SettingsScreen` / `/settings`)**:
   - بطاقة الطبيب والحساب النشط.
   - بطاقة حالة الاشتراك وتجديد الباقة.
   - الأقسام الفرعية:
     - بيانات العيادة والدكتور (`ClinicProfilePage`).
     - مشاركة كود الدعوة والصلاحيات (`StaffManagementPage`).
     - إدارة فروع العيادة وتعدد المقرات (`ClinicBranchesPage`).
     - إدارة الكشوفات والخدمات والأسعار (`ServicePricingPage`).
     - إعدادات وبوابة الواتساب السحابي (`WhatsappConfigPage`).
7. **شاشة تتبع الطابور العامة للمريض (`PatientQueueTrackingScreen` / `/track`)**:
   - واجهة مستقلة مفتوحة للمريض لمتابعة رقمه في الطابور (`#14`).
   - عدد المرضى أمامه والوقت المتبقي المتوقع.
   - بطاقة الطبيب والعيادة والاتصال المباشر.
   - خط المراحل الزمنية لرحلة الزيارة (الحجز، الوصول، الانتظار، الدخول، استلام الروشتة).

## 👁️ 5. العيوب البصرية والمشاكل المرصودة بالعين المجردة (Problems Seen on Screen)

1. **اقتطاع وتآكل النصوص (Severe Text Truncation)**:
   - في ترويسة التطبيق (`AppTopBar`): اسم العيادة مقتطع بوضوح إلى "مستشفى وعيادات الأمل ا..." رغم وجود مساحات فارغة واسعة بجانبه.
   - في قائمة المرضى (`PatientsPage`): كافة أسماء المرضى بلا استثناء مقتطعة بنقاط ("محمود ح...", "أحمد محم...", "سارة كمال..."). هذا عيب جسيم في تطبيق طبي يستوجب قراءة الاسم الثلاثي أو الرباعي كاملاً لتفادي التداخل بين المرضى.
   - في درج المواعيد الجانبي: اسم المريض مقطوع "أحمد محمود ...".
2. **فراغات مهدورة وتوزيع غير متوازن للمساحات (Wasted Canvas & Disjointed Layout)**:
   - شاشة دليل المرضى: 70% من مساحة الشاشة اليسرى عبارة عن مساحة بيضاء فارغة تماماً عند فتح الصفحة وتظهر أيقونة رمادية شاحبة في المنتصف، بينما قائمة المرضى محصورة في عمود ضيق جداً (300px) لا يتسع للبيانات.
   - شاشة تسجيل الدخول: بطاقة معلقة في منتصف الفراغ بدون أي إشارات ثقة أو مؤشرات طبية أو خلفية داعمة لعلامة العيادة.
   - شاشة تتبع الطابور للمريض: بطاقة دائرية ضخمة معلقة في منتصف شاشة سطح المكتب 1440 بمسافات هائلة على اليمين واليسار.
3. **مشاكل محاذاة في تدفق اليمين لليسار (RTL Flow Inconsistencies)**:
   - في شاشة التسجيل (`RegisterScreen`): مؤشر الخطوات `AppStepper` يعاني من انحراف في المحاذاة حيث تظهر تسمية الخطوة الأولى "الاسم ورقم التواصل" فوق الدائرة الرابعة.
   - اتجاهات الأسهم في الأزرار: بعض أزرار المتابعة تستخدم أسهماً تشير لليمين `->`، بينما في نظام RTL تعني الحركة للأمام الإشارة نحو اليسار `<-`.
4. **تشتت التدرجات وتباين الألوان (Color Noise & Contrast Issues)**:
   - ترويسة الفحص السريري وقمرة القيادة: استخدام ألوان خضراء وزرقاء فاقعة وغير موحدة مع خلفيات شفافة تضعف من قراءة المؤشرات الحيوية.
   - الرسم البياني في التقارير: موجات بيانية متقاربة وحادة بتباين لوني حاد مع اختفاء الخطوط الإرشادية لشبكة القياس.
5. **أهداف اللمس والتفاعل المتناهية الصغر (Tiny Tap Targets on Mobile/Tablet)**:
   - أيقونات القوائم الجانبية المنسدلة الثلاثية (Three-dot menus) وأزرار الإجراءات في كروت المواعيد والمرضى أصغر من الحد الأدنى المقبول سريرياً (44px) وتتطلب دقة غير عملية في بيئة العيادة السريعة.
